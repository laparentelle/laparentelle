# AGENTS.md

Astro 7 scaffold present (`src/`, `astro.config.mjs`). Deploy: Vercel (`@astrojs/vercel`). Commands: `npm run dev`, `npm run build` (production), `npm run build:preview` (Storyblok preview).

## Deploy / rendering modes (`IS_PREVIEW`)

- `IS_PREVIEW=false` → `output: 'static'`, full SSG, Storyblok **published** stories (production).
- `IS_PREVIEW=true` → `output: 'server'`, SSR, Storyblok **draft** stories (Storyblok visual preview).
- Story version logic lives in `src/lib/storyblok.ts` (draft when `DEV` or `IS_PREVIEW=true`).
- Real env vars take precedence over `.env` file — on Vercel set `IS_PREVIEW=true` on the preview project/domain.

## Stack / conventions

- Astro only. Vanilla HTML/CSS/JS in `.astro` components. Do not add a UI framework.
- Vanilla CSS co-located with components; vanilla JS scoped to the component that needs it.
- GSAP (ScrollTrigger, parallax) only when an animation need exists — not preemptively. All `src/lib` modules are `.ts` — a TS generic in a `.js` file (e.g. `toArray<HTMLElement>(…)`) silently parses as a comparison and breaks at runtime.
- Inline `onclick` JS in `.astro` is assembled by string concatenation, so brace/paren counting is manual: one stray `}` closes the IIFE early and kills the whole block with `SyntaxError: Unexpected token 'const'`. Verify with `node --check` on the rendered `onclick` attributes.
- Elements created at runtime by a dialog script (`document.createElement`) carry no `data-astro-cid-*` attribute, so component-scoped CSS does **not** apply — they need `:global(.class)` in the component `<style>` (`.book-person` / `.book-external-btn` in `Planning.astro`), else they render unstyled. Same for `<img>` rendered by the shared `SbImage.astro`: the parent's scoped image rules never match, so all SbImage-targeted selectors use `:global()` (container stays scoped, e.g. `.hero-bg :global(img)`), and every such rule must declare an explicit `height` (`auto` or `100%`) — otherwise the `height` attribute Astro emits renders literally and stretches the image.
- Forms + email automations go through Resend.

## Design system (`src/styles/design-system.css`)

- Gaia-inspired, eucalyptus-green primary (`--c-pine: #2e5249`) — never terracotta. Warm ivory bg, gold accents kept. Contrast accent: marigold (`--c-marigold: #e9a13b`) for low-contrast spots (e.g. hero primary) and buttons needing a visible hover change (e.g. activity booking).
- Fonts: Sentient (display, via Fontshare) + Jost (body) + La Belle Aurore (handwritten accents: card subtitles, testimonial signatures via `.font-hand`) via Google Fonts in `BaseLayout`.
- Primitives: `Button.astro` (`button-027` motion: primary/light/outline-light/ghost, `small`, `submit`), `.btn-row`, `.eyebrow`, `.badge`, `.blok-section`, `--radius-card`. Section components use legacy aliases (`--bg`, `--ink`, `--muted`, `--accent`, `--line`).
- Neumorphism vibe: surfaces use `--neu-surface` + dual soft shadows (`--shadow-neu`/`-sm`/`-lg`, `--shadow-neu-inset` for pressed states/inputs), no borders. Brand buttons stay solid colored (never neumorphic).
- Feature images (media_text, spotlight, person, gallery) use `.frame-organic`: 4 blob `--frame-radius` personalities (`--b/c/d` modifiers), flat with no keyline; reversed splits take B, galleries auto-cycle all 4 via `:nth-child` so neighbors differ. Card thumbnails stay plain rounded.

## Storyblok

- Content-type `page` = SEO fields + `body` (blocks) field.
- Site settings: content-type `global` (story slug `global`, always published so layouts can read it). Fields: site name/logo/favicon, SEO fallbacks, `menu_items` (`menu_item` bloks: label + multilink), CTA label/link, footer brand/tagline/address/phone/email/note, primary/accent/background hex colors. `BaseLayout` consumes it with hardcoded fallbacks; colors inject as `:root` overrides. `/global` renders the `GlobalDoc` editor documentation in preview builds only and 404s in production.
- Editor handbook: `/guide` (`src/pages/guide.astro` + `src/components/Guide.astro`) — French, non-technical documentation *for the person editing content in Storyblok* (where to click, what a field changes, annotated real screenshots, "je veux…" lookup index, pitfalls). Screenshots live in `src/assets/guide/` and are captured by `artifacts/annotate.py` (Playwright shots in `artifacts/shots/` → cropped/annotated WebP); regenerate with `python3 artifacts/annotate.py` after re-capturing. Preview-only, `noindex`, 404 in production. Since Astro still emits the imported screenshots in non-preview builds, the `dropGuideAssets()` integration in `astro.config.mjs` deletes them from `_astro/` when `IS_PREVIEW` is not `true` (production static output stays ~430 KB).
- Pages render by iterating `body` blocks; one Astro/Storyblok component per block.
- Section bloks (from lamaisongaia.fr homepage, nav/top-banner skipped): `hero`, `stats`+`stat_item`, `cards`+`card`, `membership`, `activities`+`activity`, `concept`, `gallery`+`gallery_image`, `media_text`, `spotlight`, `articles`+`article_card`, `testimonials`+`testimonial`, `cta_banner`, `newsletter`. All registered in `astro.config.mjs`.
- Richtext fields render via `renderRichText` from `@storyblok/astro`; multilink/textarea-list helpers in `src/lib/links.ts`.
- `[...slug].astro` (`prerender: false`) renders any story; `person` stories get story tags passed explicitly (`story.tag_list` is not part of `content`).
- Team model: `equipe/` folder holds `person` stories (name/role/photo/email/phone/booking/availability/bio/prestations/tarifs) + the `Notre équipe` listing page, which Storyblok pins to the folder slug → served at `/equipe`. Persons carry pole tags (`Maternité`, `Féminité`, `Parentalité`, `Bouger son corps`); the `team` blok fetches them live (`starts_with=equipe/`, filters non-person stories) with client-side tag filtering. Person flags (default true when unset): `page_enabled=false` hides the person from the listing and contact dropdown, removes practitioner profile links, and 404s the detail page. Guest practitioners (no public page) are `person` stories with `page_enabled=false`, still linked via `session.people` so names, booking routing, and slot labels keep working — the old free-text `session.practitioner` field was removed.
- Session → practitioner link: `session.people` is a References field (`options` + `is_reference_type`, restricted to `person` in `equipe/` — the API rejects a bare `reference` type) storing person UUIDs; `/api/book` resolves them via `by_uuids` and mails the booking there, admin fallback otherwise.
- Activities model (same pattern): `activites/` folder holds `activity_page` stories (title/image/animator/schedule/price/email/phone/booking/description) + listing page; `activity_catalog` blok fetches live with `Toutes/Sport/Ateliers` tag filtering (`Sport` vs `Atelier` story tags) and shows the next linked session per card. Detail template `ActivityPage` receives `story.tag_list` + `activityUuid` via the route and lists upcoming sessions. Session ↔ activity link lives on the session: `session.activity` is a single-option story reference to `activites/` (`activity_page`); activity components derive sessions via `fetchSessionsByActivity`. Homepage `activity` cards carry a single `session` reference (story UUID in `seances/`) + manual `image`/`price`/`booking_label`: the card is populated from the session (title/type/duration/practitioners/next slot, "Complet" when full) and hidden entirely when unset or past — evaluated at build time in production SSG, so the homepage needs regular rebuilds (Storyblok webhook) to stay fresh. The card "Réserver" button links to the planning deep-linked on the featured session's day (`/programme-du-mois?date=AAAA-MM-JJ`, honored by the planning's `data-day` markers + `?date=` script; unknown dates fall back to the first page). Booking dialog is `src/components/BookDialog.astro` rendered once per page by `BaseLayout`; openers built by `buildBookOpener` in `src/lib/bookDialog.ts` (string-concatenated IIFE — same brace-counting care + `node --check` rule as above).
- Contact form (`ContactForm.astro` + `src/lib/contacts.ts`): fields Nom/Prénom/Email/Message/Destinataire. General mode builds the recipient dropdown live from `equipe/` emails (`Administratif` = `CONTACT_TO_EMAIL` first); fixed mode (`fixedEmail`, used on person pages + `contact` blok `person` mode) hides the dropdown. Person pages without an email fall back to the admin address. `/api/contact` only delivers to allowlisted addresses — never trust client input.
- Planning (`/programme-du-mois`): one `planning` story holds a `sessions` references field (session story UUIDs, editorial order) pointing at `session` stories in `seances/` — **the session story UUID is the booking key** (stable across edits; never hand-write one). Session `type` (not `kind`): `activite` | `sport` | `bienetre` | `consultation`, driving the filter chips, badges and slot colours. Session checkbox `external_booking` (default false when unset): hides the planning form for that slot — the dialog shows "La réservation de ce créneau ne passe pas par le planning." + a marigold "Réserver directement" button to the linked practitioner's `booking_link` (profile page fallback when unset, contact fallback when neither), no spots badge, and `/api/book` rejects the uid with 400. Component filters to the next 30 days, shown 4 days at a time with prev/next nav (empty days stay visible; grid on desktop ≥64rem, day cards on mobile). Remaining spots = `capacity` − active Supabase count; without `SUPABASE_URL`/`SUPABASE_SERVICE_ROLE_KEY` the page degrades to a phone/contact note instead of booking buttons. `seances/*` stories 404 via `[...slug].astro` (rendered only through planning/activities).
- Bookings: `src/lib/bookings.ts` (PostgREST via fetch, server-only service key) + `/api/book` (capacity check → insert → Resend confirmation, honeypot). `session_uid` is the session story UUID (pre-migration rows keyed by blok `_uid` are orphaned and ignored by counts). Cancellations use `/annulation` + `/api/cancel`, separate client/staff UUID tokens, soft-cancelled status, client cutoff 24h before the session, active-count availability, and ICS cancellation updates. Table DDL in `supabase/migrations/001_bookings.sql` and `002_booking_cancellations.sql`.
- Storyblok `datetime` fields only render in the editor when the value is **UTC ISO with Z** (`2026-09-28T16:30:00.000Z`). `+02:00` offsets and `YYYY-MM-DD HH:MM:SS` are stored but show as empty. Always write Paris times converted to UTC (`src/lib/date.ts` parses both safely). Storage is always UTC; the "UTC+00:00" chip in the field is the *user* timezone (`PUT /v1/users/me {user:{timezone}}`, set to `Europe/Paris`) and only affects display/entry.
- Storyblok `number` fields reject JSON ints: the API wants a **string of digits** (`"60"`, not `60`) — sending an int returns 422 "must be a string with numbers". Session `duration` is a `number` field holding minutes, sent as `"60"`.
- SEO (`src/lib/seo.ts` + `BaseLayout` head): canonical origin resolves `PUBLIC_SITE_URL` → `Astro.site` → request origin — set `PUBLIC_SITE_URL` on Vercel (production domain) or canonical/og/sitemap ship the request host (a build warning fires when it is unset). Head order follows htmlhead.dev (charset → viewport → title → description/robots → canonical → OG → Twitter → theme-color → preconnect → CSS → icons → JSON-LD). Auto schema: Organization/LocalBusiness + WebSite + BreadcrumbList in the head `@graph`; FAQPage from `Faq.astro`, Event from `Planning.astro` (first 40 slots, no `offers` on external sessions) and `ActivityPage.astro` (first 12), Person from `Person.astro` — component schemas render inline in the body and reference `#organization` by `@id`. Editor fields: `global` (`theme_color`, `og_image`, `twitter_site`/`twitter_creator`, `same_as` one URL/line, `geo_latitude`/`geo_longitude`) + `page` (`seo_image`, `og_type`, `canonical_url`, `robots`, `schema_manual`; `person`/`activity_page` carry `schema_manual` only). DEV and `IS_PREVIEW=true` force `noindex, nofollow` on every page; production relies on the editor `robots` field (default `index, follow`). `/sitemap.xml` (`src/pages/sitemap.xml.ts`, prerendered in prod) lists published `page`/`person` (page enabled)/`activity_page` stories and skips noindex ones — it uses raw `fetch`, never `useStoryblokApi` (page-context only, silent empty sitemap otherwise). `/robots.txt` (`src/pages/robots.txt.ts`) blocks everything in preview, allows + points at the sitemap in production.
- After editing `astro.config.mjs`, restart the dev server (`npx astro dev stop` + `npm run dev`) — component registration is not hot-reloaded.

## Gotchas (verified during setup)

- `@storyblok/astro` has no default export: `import { storyblok } from '@storyblok/astro'`, and `StoryblokComponent` is a separate path: `import StoryblokComponent from '@storyblok/astro/StoryblokComponent.astro'`.
- `components` map paths are relative to `componentsDir: 'src'` — e.g. `page: 'components/storyblok/Page'`.
- `@astrojs/vercel` adapter. Contact form needs `RESEND_API_KEY` + `CONTACT_TO_EMAIL` (see `.env.example`).
- Env: copy `.env.example` to `.env`. Without a real `STORYBLOK_TOKEN`, `/` renders a static placeholder (by design).
- Testing email flows: ALWAYS ask the user before submitting any test booking/cancellation — every submission sends real Resend emails. `CONTACT_TO_EMAIL` (`laparentelle.contact@gmail.com`) is a live mailbox the user cannot access; use only `huitquatre.dev@gmail.com` as the test client address.
